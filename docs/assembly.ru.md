# Сборка и прошивка — пошагово

Эта инструкция для **LCD-прототипа** с работающим NASA Duet внутри системы.
Она не позволяет выбросить электронику прибора и вставить датчики в ESP32.
До пайки подтвердить ревизию по [списку фотографий](standalone.ru.md).
Если опыта нет, передать разделы 2–4 мастеру по электронике.

## 1. Подготовка и исходные показания

Записать текущие настройки NASA: единицы, keel offset, калибровку лага, gain
threshold и тревоги. Сфотографировать их. Проверить, что оба датчика исправны
со штатным прибором. Сохранить LCD и кнопки: первый запуск требует сравнения
показаний, а настройка остаётся на NASA.

Нужны [детали](bom.ru.md) и [таблица соединений](../hardware/README.ru.md).
Буквы GPIO обозначают функцию вывода ESP32, а не порядковый номер ножки платы.
Питать адаптер нужно от 12 В через преобразователь 5 В. CAN не подключать
на первых шагах.

## 2. Собрать питание без ESP32 и NASA

1. Отключить аккумуляторную линию, USB и NMEA. Проверить мультиметром отсутствие питания.
2. Собрать F1, D1, TVS и конденсаторы по аппаратной схеме. У диода полоска — катод;
   у электролитического конденсатора полоса обычно помечает отрицательную ножку.
3. Подключить DC/DC, оставив выход без нагрузки. На стенде установить 12 В,
   ограничение тока 0,25 А для адаптера; NASA пока отключён.
4. Измерить выход относительно GND: примерно 5 В, в пределах 4,75–5,25 В.
   При ошибке полярности/напряжения отключить питание и найти её.
5. Снять питание, подключить ESP32 к входу 5V и GND. Проверить его 3V3:
   примерно 3,3 В. Если БП постоянно в ограничении — не увеличивать его вслепую.

## 3. Собрать входной буфер

При снятом питании собрать SN74LVC125A и его обвязку. Прозвонить каждую цепь
по таблице, убедиться в отсутствии мостиков пайки. Пока NASA не подключён,
проверить буфер подачей на каждый вход сначала 0 В, затем 5 В от лабораторного
источника через предусмотренный резистор. На соответствующем выходе должны
быть 0 и приблизительно 3,3 В. 5 В на выходе — ошибка подключения.

На обесточенном NASA подтвердить точки DATA/WR/CS/GND прозвонкой и припаять
четыре коротких провода, разгрузить их механически. Сигнальные выводы NASA
соединять только со входами буфера, не прямо с ESP32. Не трогать цепь
возбуждения датчика глубины. Не удлинять и не обрезать штатный коаксиальный кабель.

## 4. Собрать CAN, пока без магистрали

Подготовить MIKROE-2627 по аппаратной инструкции: VIO=3V3, HI, убрать его
R2/R3-терминацию, проверить TXD/RXD и DB9. Подать 5 В и 3,3 В, проверить
уровень RXD относительно локальной земли. Соединить GPIO21/22, добавить
pull-up TXD. Измерить отсутствие короткого замыкания GND_LOCAL↔GND_ISO
на отдельном, полностью отключённом адаптере. Конденсаторы могут дать краткую
реакцию омметра, но постоянной низкоомной связи быть не должно.

NET-S красный провод и экран кабеля индивидуально изолировать; соединить
CAN-H, CAN-L и NET-C по таблице. ARM пока открыт. Прочитать инструкцию
разъёма, поскольку вид со стороны кабеля зеркален виду контактов.

## 5. Установить среду и записать диагностическую прошивку

Самый удобный вариант — Visual Studio Code с расширением **PlatformIO IDE**.
Скачать репозиторий кнопкой Code → Download ZIP и распаковать либо клонировать
Git. В VS Code выбрать Open Folder и открыть папку, где лежит `platformio.ini`.
Нужна ветка с этим проектом; до слияния pull request — `codex/esp32-prototype`.

Командный вариант для macOS/Linux (из папки проекта):

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install platformio==6.1.18
python -m platformio run
python -m platformio device list
```

Для Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install platformio==6.1.18
.\.venv\Scripts\python.exe -m platformio run
.\.venv\Scripts\python.exe -m platformio device list
```

В дальнейших командах Windows заменить `python` на
`.\.venv\Scripts\python.exe`. PlatformIO загрузит компилятор и зафиксированные
библиотеки; нужен доступ в интернет. Сборка должна закончиться `SUCCESS`.

**Для прошивки отключить от ESP32 внешние 5V, все провода NASA и CAN-модуля**
(включая питание модуля от ESP32). Оставить только USB. Это исключает обратное
питание от USB через макет и соединение компьютера с судовой проводкой.
Для многократной диагностики под внешним питанием использовать отдельно
проверенный USB-изолятор/схему питания, а не два источника 5 В одновременно.

```sh
python -m platformio run -t upload
python -m platformio device monitor
```

Если найдено несколько портов:

```sh
python -m platformio run -t upload --upload-port /dev/cu.usbserial-XXXX
python -m platformio device monitor --port /dev/cu.usbserial-XXXX
```

На Windows пример порта `COM5`; выбрать реальный из `device list`. При
`Connecting...` удерживать BOOT, коротко нажать EN, отпустить BOOT после начала
записи. Сначала проверить кабель с передачей данных и закрыть Serial Monitor.
Не стирать всю flash без необходимости. `firmware.bin` — только приложение;
не записывать его на адрес 0. Команда PlatformIO сама записывает bootloader,
таблицу разделов и приложение с правильными адресами. Это основной способ
установки; ручная запись CI-артефактов не требуется.

## 6. Проверить чтение NASA

Для USB-диагностики на столе можно питать **ESP32 и весь адаптер только от USB**,
при физически отключённом выходе 5 В DC/DC. USB должен обеспечивать необходимый
ток. NASA питать от отдельного ограниченного 12-В источника с общей GND_LOCAL.
CAN-модуль оставить отключённым от судовой сети. Не соединять несколько
источников 5 В. На лодке безопаснее записать прошивку отдельно, а диагностику
проводить с квалифицированным специалистом и проверенной развязкой компьютера.

После включения NASA в режиме SPEED в мониторе 115200 baud ожидается:

```text
DIY Duet prototype 0.1.0; CAN=OFF (diagnostics only); depth_reference=UNVERIFIED: depth NA
frames=... rejected=0 depth_m=12.300 stw_mps=2.778 screen=1 tx_fail=0
```

Числа приведены как пример, **не как встроенные тестовые показания**.
`nan` означает отсутствие достоверного значения. Без NASA это нормальный результат.
Если `frames` не растёт или `rejected` постоянно растёт, не включать передачу:
снять запись DATA/WR/CS после буфера и проверить 137 бит, адрес 0 и фронт WR.
Прошивка намеренно не подбирает автоматически другую карту сегментов.

Сравнить несколько значений глубины/скорости с NASA, затем метры/футы,
узлы/км/ч/mph. Проверить меню и режимы TRIP/TOTAL: скорость должна стать `nan`.
При настоящем OUT глубина должна стать `nan`. Не имитировать эхо пальцем
в разъёме или замыканием его контактов. Отключение цифрового tap-кабеля должно
приводить к `nan` не позднее 2 секунд после последнего принятого кадра.

## 7. Задать точку отсчёта глубины

NASA уже вычитает свой keel offset из отображаемой глубины. Чтобы не вычесть
его дважды, в этой версии **установить keel offset NASA в 0,0** и подтвердить
сравнением с глубиной от датчика. Нужную поправку задавать только в адаптере.
Если оставить старую настройку, данные PGN будут иметь неверную точку отсчёта.

Создать `include/local_config.h` копированием `local_config.example.h`:

```cpp
#pragma once
#define DUET_COMMISSIONED 1
#define DUET_ZERO_OFFSET_VERIFIED 1
#define DUET_OUTPUT_OFFSET_M -1.2
```

`-1.2` здесь только пример: киль расположен на 1,2 м ниже датчика. Внести
своё измеренное расстояние либо 0 для глубины от датчика. Для глубины от
ватерлинии offset положительный. Прошивка передаёт глубину от датчика и
поправку раздельно; поведение MFD проверить. Например: 5,0 м от датчика и
offset −1,2 м дают 3,8 м под килем на дисплее, который учитывает поправку.
Не включать ещё одну идентичную поправку в MFD.

Калибровка лага остаётся в NASA. Повторно её в адаптере применять не нужно.
После изменения параметров NASA снова проверить нулевой offset. Флаг в
прошивке — подтверждение пользователя, автоматического чтения настройки нет.

Повторить сборку и запись из шага 5. Перемычку ARM поставить при снятом питании.
Если нулевой offset не подтверждён, глубина в CAN остаётся NA.

## 8. Испытать на NMEA 2000

1. Сначала отдельная тестовая сеть: штатное питание, два терминатора, T и MFD
   или USB-CAN. Измерить сопротивление обесточенной сети до подключения адаптера.
2. Подключить адаптер, проверить сопротивление снова, включить сеть и питание адаптера.
3. Найти устройство `DIY Duet Bridge`, выбрать его источником глубины и STW.
4. Проверить PGN 128267/128259 и точку отсчёта, затем отключить tap-поток:
   MFD должен показывать отсутствие данных. Если держит старое значение —
   выяснить настройки/поведение MFD до эксплуатации.
5. Проверить перезапуск NASA, адаптера и MFD по отдельности. Без ARM при
   загрузке узел не появится: это ожидаемо. Снятие ARM во время работы выдаёт NA.
6. Повторить сравнение под мотором, с насосом/зарядкой и на разных глубинах.
   Перезапуск CAN после тяжёлых ошибок bus-off отдельно проверить: автоматическое
   восстановление драйвера этой версией проекта не подтверждено.

До завершения этих испытаний не использовать прототип как единственный источник
глубины. Тревоги NASA в MFD не переносятся; настроить тревоги на MFD и проверить их.

## 9. Корпус и установка

Печатать корпус по фактическим размерам адаптера, не наоборот. Включённый OpenSCAD
— шаблон только **дополнительной** коробки. Исходный NASA остаётся рядом, чтобы
провод цифровых сигналов был коротким. Прототип ставится в сухом внутреннем месте.
После установки проверить нагрев, отсутствие помех и разгрузку всех кабелей.

Для возврата к исходной системе отключить питание, снять адаптер и четыре
tap-провода, восстановить записанный keel offset NASA. Датчики не менялись.
